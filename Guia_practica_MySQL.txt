Guía práctica de MySQL paso a paso
De cero a consultas, joins, procedimientos y respaldos, con datos de ejemplo y ejercicios resueltos.
1. Introducción
MySQL es un sistema gestor de bases de datos relacionales (RDBMS) de código abierto, mantenido por Oracle.
Guarda la información en tablas (filas y columnas) y se consulta con SQL. Es muy usado en aplicaciones web
(WordPress, Laravel, PHP, Node.js).
Conceptos básicos
• Base de datos (schema): contenedor de tablas, vistas y procedimientos. En MySQL, database y schema son
sinónimos.
• Tabla: conjunto de filas (registros) y columnas (campos).
• Clave primaria (PK): identifica de forma única cada fila.
• Clave foránea (FK): apunta a la PK de otra tabla y crea la relación.
• Motor de almacenamiento: InnoDB es el predeterminado; soporta transacciones y claves foráneas.
Herramientas
• MySQL Server: el servidor (Community Edition, gratuito).
• MySQL Workbench: interfaz gráfica para escribir consultas y administrar.
• Cliente de línea de comandos (mysql): para trabajar desde la terminal.
Clasificación de los comandos SQL
Tipo Significado Comandos
DDL Define estructuras CREATE, ALTER, DROP, TRUNCATE
DML Manipula datos INSERT, UPDATE, DELETE
DQL Consulta datos SELECT
DCL Permisos GRANT, REVOKE
TCL Transacciones START TRANSACTION, COMMIT, ROLLBACK
2. Preparar el entorno
1. Descarga MySQL Community Server y MySQL Workbench desde el sitio oficial (el instalador de Windows incluye
ambos).
2. Durante la instalación define la contraseña del usuario root y guárdala.
3. Abre MySQL Workbench y conéctate a la instancia local (localhost, puerto 3306).
4. Abre una pestaña de consulta (SQL Editor). Ejecuta con el rayo o con Ctrl+Enter (la línea actual) o
Ctrl+Shift+Enter (todo el script).
Desde terminal:
mysql -u root -p
Cada comando SQL termina en punto y coma (;). Los bloques de esta guía se ejecutan en orden.

4.1 Operadores y valores especiales
• Comparación: =, <> o !=, >, <, >=, <=.
• Lógicos: AND, OR, NOT.
• NULL significa "sin valor": se compara con IS NULL / IS NOT NULL, nunca con = NULL.
5. Crear tablas
Vamos a modelar una tienda con cuatro tablas: clientes, productos, pedidos y detalle_pedido.
CREATE TABLE clientes (
 cliente_id INT AUTO_INCREMENT PRIMARY KEY,
 nombre VARCHAR(50) NOT NULL,
 apellido VARCHAR(50) NOT NULL,
 email VARCHAR(100) UNIQUE,
 ciudad VARCHAR(50),
 fecha_alta DATE DEFAULT (CURRENT_DATE)
) ENGINE=InnoDB;
CREATE TABLE productos (
 producto_id INT AUTO_INCREMENT PRIMARY KEY,
 nombre VARCHAR(80) NOT NULL,
 categoria VARCHAR(40),
 precio DECIMAL(10,2) NOT NULL CHECK (precio > 0),
 stock INT NOT NULL DEFAULT 0
) ENGINE=InnoDB;
CREATE TABLE pedidos (
 pedido_id INT AUTO_INCREMENT PRIMARY KEY,
 cliente_id INT NOT NULL,
 fecha DATE NOT NULL DEFAULT (CURRENT_DATE),
 estado VARCHAR(20) NOT NULL DEFAULT 'Pendiente',
 CONSTRAINT fk_pedidos_clientes
 FOREIGN KEY (cliente_id) REFERENCES clientes(cliente_id)
) ENGINE=InnoDB;
CREATE TABLE detalle_pedido (
 detalle_id INT AUTO_INCREMENT PRIMARY KEY,
 pedido_id INT NOT NULL,
 producto_id INT NOT NULL,
 cantidad INT NOT NULL CHECK (cantidad > 0),
 CONSTRAINT fk_detalle_pedidos
 FOREIGN KEY (pedido_id) REFERENCES pedidos(pedido_id),
 CONSTRAINT fk_detalle_productos
 FOREIGN KEY (producto_id) REFERENCES productos(producto_id)
) ENGINE=InnoDB;
Restricciones usadas
• PRIMARY KEY: identificador único, no nulo.
• AUTO_INCREMENT: número automático que avanza de 1 en 1.
• NOT NULL: el campo es obligatorio.
• UNIQUE: no permite valores repetidos.
• DEFAULT: valor automático si no se indica (las expresiones van entre paréntesis, como (CURRENT_DATE)).
• CHECK: valida una condición (se aplica desde MySQL 8.0.16).
• FOREIGN KEY: garantiza la integridad referencial.

8. Funciones de agregación y agrupación
SELECT COUNT(*) AS total_productos,
 AVG(precio) AS precio_promedio,
 MIN(precio) AS precio_minimo,
 MAX(precio) AS precio_maximo,
 SUM(stock) AS stock_total
FROM productos;
GROUP BY agrupa filas; HAVING filtra los grupos (WHERE filtra filas antes de agrupar).
SELECT categoria, COUNT(*) AS cantidad, ROUND(AVG(precio), 2) AS precio_promedio
FROM productos
GROUP BY categoria;
SELECT categoria, COUNT(*) AS cantidad
FROM productos
GROUP BY categoria
HAVING COUNT(*) >= 2;
9. JOINs: relacionar tablas
Un JOIN combina filas de dos o más tablas con una condición, normalmente PK = FK.
JOIN Resultado ¿Soportado en MySQL?
INNER JOIN Solo filas con coincidencia en ambas tablas Sí
LEFT JOIN Todas las de la izquierda y las coincidentes de la derecha
(NULL si no hay) Sí
RIGHT JOIN Todas las de la derecha y las coincidentes de la izquierda Sí
FULL JOIN Todas las filas de ambas tablas No directo: se simula con UNION
CROSS JOIN Todas las combinaciones posibles Sí
SELF JOIN Una tabla unida consigo misma (con alias) Sí
9.1 INNER JOIN
SELECT p.pedido_id, c.nombre, c.apellido, p.fecha, p.estado
FROM pedidos p
INNER JOIN clientes c ON c.cliente_id = p.cliente_id;
9.2 JOIN de varias tablas: detalle de cada pedido
SELECT p.pedido_id,
 CONCAT(c.nombre, ' ', c.apellido) AS cliente,
 pr.nombre AS producto,
 d.cantidad,
 pr.precio,
 d.cantidad * pr.precio AS subtotal
FROM pedidos p
JOIN clientes c ON c.cliente_id = p.cliente_id
JOIN detalle_pedido d ON d.pedido_id = p.pedido_id
JOIN productos pr ON pr.producto_id = d.producto_id
ORDER BY p.pedido_id;
En MySQL se concatena con CONCAT() (el operador + suma números, no une texto).
9.3 LEFT JOIN: clientes sin pedidos
SELECT c.cliente_id, c.nombre, c.apellido
FROM clientes c
LEFT JOIN pedidos p ON p.cliente_id = c.cliente_id
WHERE p.pedido_id IS NULL;
Resultado esperado: Sofía Torres.
9.4 RIGHT JOIN: todos los productos, se hayan vendido o no
SELECT pr.producto_id, pr.nombre, d.pedido_id, d.cantidad
FROM detalle_pedido d
RIGHT JOIN productos pr ON pr.producto_id = d.producto_id
ORDER BY pr.producto_id;
Bocina Bluetooth aparece con NULL en pedido_id y cantidad porque nunca se vendió.
9.5 FULL JOIN simulado con UNION
MySQL no tiene FULL JOIN. Se obtiene uniendo un LEFT JOIN y un RIGHT JOIN:
SELECT c.cliente_id, c.nombre, p.pedido_id, p.estado
FROM clientes c
LEFT JOIN pedidos p ON p.cliente_id = c.cliente_id
UNION
SELECT c.cliente_id, c.nombre, p.pedido_id, p.estado
FROM clientes c
RIGHT JOIN pedidos p ON p.cliente_id = c.cliente_id;
UNION elimina duplicados; UNION ALL los conserva. Con la FK fk_pedidos_clientes no existen pedidos sin
cliente, así que aquí el resultado es igual al del LEFT JOIN. El patrón es útil al comparar tablas sin FK entre ellas.
9.6 CROSS JOIN: todas las combinaciones
No usa ON: combina cada fila de una tabla con cada fila de la otra. Con 3 filas y 4 filas devuelve 12.
SELECT c.ciudad, cat.categoria
FROM (SELECT DISTINCT ciudad FROM clientes) c
CROSS JOIN (SELECT DISTINCT categoria FROM productos) cat
ORDER BY c.ciudad, cat.categoria;
9.7 SELF JOIN: una tabla consigo misma
CREATE TABLE empleados (
 empleado_id INT PRIMARY KEY,
 nombre VARCHAR(50) NOT NULL,
 jefe_id INT NULL,
 CONSTRAINT fk_empleados_jefe FOREIGN KEY (jefe_id) REFERENCES empleados(empleado_id)
) ENGINE=InnoDB;
INSERT INTO empleados (empleado_id, nombre, jefe_id) VALUES
(1, 'Roberto', NULL),
(2, 'Elena', 1),
(3, 'Miguel', 1),
(4, 'Laura', 2),
(5, 'Pedro', 2);
SELECT e.nombre AS empleado,
 j.nombre AS jefe
FROM empleados e
LEFT JOIN empleados j ON j.empleado_id = e.jefe_id;
Roberto aparece con NULL como jefe; con INNER JOIN quedaría fuera.
9.8 Contar incluyendo ceros
SELECT c.cliente_id,
 c.nombre,
 COUNT(p.pedido_id) AS total_pedidos
FROM clientes c
LEFT JOIN pedidos p ON p.cliente_id = c.cliente_id
GROUP BY c.cliente_id, c.nombre
ORDER BY total_pedidos DESC;
Usa COUNT(p.pedido_id) y no COUNT(*): COUNT(*) contaría la fila vacía del LEFT JOIN y devolvería 1 en lugar
de 0.
9.9 ON contra WHERE en un LEFT JOIN
-- Filtro en ON: se conservan TODOS los clientes
SELECT c.nombre, p.pedido_id, p.estado
FROM clientes c
LEFT JOIN pedidos p
 ON p.cliente_id = c.cliente_id AND p.estado = 'Pendiente';
-- Filtro en WHERE: se descartan los clientes sin pedidos pendientes
SELECT c.nombre, p.pedido_id, p.estado
FROM clientes c
LEFT JOIN pedidos p ON p.cliente_id = c.cliente_id
WHERE p.estado = 'Pendiente';
Regla práctica: el filtro sobre la tabla de la derecha va en ON si quieres conservar las filas de la izquierda; el de la
izquierda va en WHERE.
9.10 Total por pedido y por cliente
SELECT p.pedido_id,
 SUM(d.cantidad * pr.precio) AS total_pedido
FROM pedidos p
JOIN detalle_pedido d ON d.pedido_id = p.pedido_id
JOIN productos pr ON pr.producto_id = d.producto_id
GROUP BY p.pedido_id;
SELECT c.nombre, c.apellido,
 SUM(d.cantidad * pr.precio) AS total_gastado
FROM clientes c
JOIN pedidos p ON p.cliente_id = c.cliente_id
JOIN detalle_pedido d ON d.pedido_id = p.pedido_id
JOIN productos pr ON pr.producto_id = d.producto_id
GROUP BY c.cliente_id, c.nombre, c.apellido
ORDER BY total_gastado DESC;
10. Modificar y eliminar datos
Regla de oro: usa siempre WHERE en UPDATE y DELETE. Sin él afectas todas las filas. Prueba antes con un
SELECT con la misma condición.
MySQL Workbench activa por defecto el modo seguro (sql_safe_updates): rechaza UPDATE y DELETE sin WHERE
sobre columnas con índice. Es una protección útil; no la desactives sin necesidad.
-- UPDATE
UPDATE productos
SET stock = 50
WHERE nombre = 'Bocina Bluetooth';
UPDATE productos
SET precio = precio * 1.10
WHERE categoria = 'Accesorios';
-- DELETE (Sofía no tiene pedidos, se puede borrar)
DELETE FROM clientes WHERE cliente_id = 5;
Si intentas borrar un cliente con pedidos, MySQL lo bloquea por la clave foránea (error 1451). Borra primero sus
pedidos o crea la FK con ON DELETE CASCADE.
TRUNCATE TABLE tabla; -- vacía la tabla y reinicia AUTO_INCREMENT (no admite WHERE)
DROP TABLE tabla; -- elimina la tabla completa
DROP TABLE IF EXISTS tabla;
ALTER TABLE clientes ADD COLUMN telefono VARCHAR(20);
ALTER TABLE clientes MODIFY COLUMN telefono VARCHAR(30);
ALTER TABLE clientes DROP COLUMN telefono;
11. Subconsultas y CTE
-- Productos con precio mayor al promedio
SELECT nombre, precio
FROM productos
WHERE precio > (SELECT AVG(precio) FROM productos);
-- Clientes con al menos un pedido
SELECT nombre, apellido
FROM clientes
WHERE cliente_id IN (SELECT cliente_id FROM pedidos);
Las CTE (WITH) están disponibles desde MySQL 8.0 y vuelven más legibles las consultas:
WITH totales AS (
 SELECT d.pedido_id, SUM(d.cantidad * pr.precio) AS total
 FROM detalle_pedido d
 JOIN productos pr ON pr.producto_id = d.producto_id
 GROUP BY d.pedido_id
)
SELECT p.pedido_id, p.cliente_id, t.total
FROM pedidos p
JOIN totales t ON t.pedido_id = p.pedido_id
WHERE t.total > 100;

13. Vistas
Una vista es una consulta guardada que se usa como una tabla.
CREATE VIEW vw_detalle_pedidos AS
SELECT p.pedido_id,
 CONCAT(c.nombre, ' ', c.apellido) AS cliente,
 pr.nombre AS producto,
 d.cantidad,
 d.cantidad * pr.precio AS subtotal
FROM pedidos p
JOIN clientes c ON c.cliente_id = p.cliente_id
JOIN detalle_pedido d ON d.pedido_id = p.pedido_id
JOIN productos pr ON pr.producto_id = d.producto_id;
SELECT * FROM vw_detalle_pedidos WHERE subtotal > 100;
14. Procedimientos almacenados y funciones
En el cliente (Workbench o terminal) se cambia el delimitador con DELIMITER para que el ; interno no corte la
definición.
DELIMITER //
CREATE PROCEDURE sp_pedidos_por_cliente(IN p_cliente_id INT)
BEGIN
 SELECT pedido_id, fecha, estado
 FROM pedidos
 WHERE cliente_id = p_cliente_id;
END //
CREATE PROCEDURE sp_agregar_producto(
 IN p_nombre VARCHAR(80),
 IN p_categoria VARCHAR(40),
 IN p_precio DECIMAL(10,2),
 IN p_stock INT)
BEGIN
 INSERT INTO productos (nombre, categoria, precio, stock)
 VALUES (p_nombre, p_categoria, p_precio, p_stock);
END //
CREATE FUNCTION fn_precio_con_impuesto(p_precio DECIMAL(10,2))
RETURNS DECIMAL(10,2)
DETERMINISTIC
BEGIN
 RETURN ROUND(p_precio * 1.07, 2);
END //
DELIMITER ;
CALL sp_pedidos_por_cliente(1);
CALL sp_agregar_producto('Webcam HD', 'Accesorios', 55.00, 25);
SELECT nombre, fn_precio_con_impuesto(precio) AS precio_final FROM productos;
Los procedimientos se ejecutan con CALL; las funciones se usan dentro de un SELECT.
15. Transacciones
Una transacción agrupa operaciones: o se ejecutan todas o ninguna (propiedades ACID). Requiere el motor
InnoDB.
START TRANSACTION;
INSERT INTO pedidos (cliente_id, estado) VALUES (2, 'Pendiente');
SET @nuevo_pedido = LAST_INSERT_ID();
INSERT INTO detalle_pedido (pedido_id, producto_id, cantidad)
VALUES (@nuevo_pedido, 3, 1);
UPDATE productos SET stock = stock - 1 WHERE producto_id = 3;
COMMIT; -- confirma los cambios
-- ROLLBACK; -- en lugar de COMMIT, deshace todo
• LAST_INSERT_ID() devuelve el último AUTO_INCREMENT generado.
• Por defecto MySQL usa autocommit = 1: cada sentencia se confirma sola. START TRANSACTION lo suspende
hasta el COMMIT o ROLLBACK.
16. Triggers (disparadores)
Un trigger se ejecuta automáticamente ante un INSERT, UPDATE o DELETE. Usa OLD (valor anterior) y NEW (valor
nuevo).
CREATE TABLE log_productos (
 log_id INT AUTO_INCREMENT PRIMARY KEY,
 producto_id INT,
 precio_anterior DECIMAL(10,2),
 precio_nuevo DECIMAL(10,2),
 fecha_cambio DATETIME DEFAULT CURRENT_TIMESTAMP
);
DELIMITER //
CREATE TRIGGER trg_cambio_precio
AFTER UPDATE ON productos
FOR EACH ROW
BEGIN
 IF OLD.precio <> NEW.precio THEN
 INSERT INTO log_productos (producto_id, precio_anterior, precio_nuevo)
 VALUES (OLD.producto_id, OLD.precio, NEW.precio);
 END IF;
END //
DELIMITER ;
UPDATE productos SET precio = 900 WHERE producto_id = 1;
SELECT * FROM log_productos;
17. Índices
Un índice acelera las búsquedas a cambio de espacio y de escrituras más lentas.
CREATE INDEX ix_clientes_ciudad ON clientes (ciudad);
CREATE INDEX ix_pedidos_cliente_fecha ON pedidos (cliente_id, fecha);
SHOW INDEX FROM clientes;
DROP INDEX ix_clientes_ciudad ON clientes;
• La PK y las FK crean índices automáticamente en InnoDB.
• Indexa las columnas usadas en WHERE, JOIN y ORDER BY.
• EXPLAIN muestra cómo MySQL ejecuta una consulta:
EXPLAIN SELECT * FROM clientes WHERE ciudad = 'Miami';
18. Usuarios y permisos
CREATE USER 'ventas'@'localhost' IDENTIFIED BY 'Cambiar_Esta_Clave_123!';
GRANT SELECT, INSERT ON tienda_db.pedidos TO 'ventas'@'localhost';

DROP USER 'ventas'@'localhost';
Buenas prácticas: dar solo los permisos mínimos necesarios, usar contraseñas robustas y no usar root en las
aplicaciones.
19. Respaldo y restauración
Se ejecutan desde la terminal (no desde el editor SQL):
# Respaldo de una base de datos
mysqldump -u root -p tienda_db > tienda_db.sql
# Respaldo con rutinas y triggers
mysqldump -u root -p --routines --triggers tienda_db > tienda_db_completo.sql
# Restaurar (la base de datos debe existir)
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS tienda_db"
mysql -u root -p tienda_db < tienda_db.sql
En Workbench también puedes usar Server > Data Export y Data Import.
20. Ejercicios con solución
Ejercicio 1. Productos de la categoría Accesorios ordenados por precio de menor a mayor.
SELECT nombre, precio
FROM productos
WHERE categoria = 'Accesorios'
ORDER BY precio ASC;
Ejercicio 2. Clientes por ciudad.
SELECT ciudad, COUNT(*) AS total_clientes
FROM clientes
GROUP BY ciudad;
Ejercicio 3. Pedidos con el nombre completo del cliente y su estado.
SELECT p.pedido_id, CONCAT(c.nombre, ' ', c.apellido) AS cliente, p.estado
FROM pedidos p
JOIN clientes c ON c.cliente_id = p.cliente_id;
Ejercicio 4. Cada producto con la cantidad total vendida (0 si nunca se vendió).
SELECT pr.nombre, IFNULL(SUM(d.cantidad), 0) AS unidades_vendidas
FROM productos pr
LEFT JOIN detalle_pedido d ON d.producto_id = pr.producto_id
GROUP BY pr.producto_id, pr.nombre
ORDER BY unidades_vendidas DESC;
Ejercicio 5. Clientes que compraron productos de la categoría Audio, sin repetir.
SELECT DISTINCT c.nombre, c.apellido
FROM clientes c
JOIN pedidos p ON p.cliente_id = c.cliente_id
JOIN detalle_pedido d ON d.pedido_id = p.pedido_id
JOIN productos pr ON pr.producto_id = d.producto_id
WHERE pr.categoria = 'Audio';
Ejercicio 6. Pedidos cuyo total supera 100, con el nombre del cliente.
SELECT p.pedido_id,
 CONCAT(c.nombre, ' ', c.apellido) AS cliente,
 SUM(d.cantidad * pr.precio) AS total
FROM pedidos p
JOIN clientes c ON c.cliente_id = p.cliente_id
JOIN detalle_pedido d ON d.pedido_id = p.pedido_id
JOIN productos pr ON pr.producto_id = d.producto_id
GROUP BY p.pedido_id, c.nombre, c.apellido
HAVING SUM(d.cantidad * pr.precio) > 100
ORDER BY total DESC;
Ejercicio 7. Cada empleado con su jefe y el jefe de su jefe.
SELECT e.nombre AS empleado, j.nombre AS jefe, s.nombre AS jefe_superior
FROM empleados e
LEFT JOIN empleados j ON j.empleado_id = e.jefe_id
LEFT JOIN empleados s ON s.empleado_id = j.jefe_id;
Ejercicio 8. Producto más vendido por unidades.
SELECT pr.nombre, SUM(d.cantidad) AS unidades_vendidas
FROM detalle_pedido d
JOIN productos pr ON pr.producto_id = d.producto_id
GROUP BY pr.producto_id, pr.nombre
ORDER BY unidades_vendidas DESC
LIMIT 1;
Ejercicio 9. Aumenta 5 % el precio de los productos de Audio y verifica.
UPDATE productos
SET precio = ROUND(precio * 1.05, 2)
WHERE categoria = 'Audio';
SELECT nombre, precio FROM productos WHERE categoria = 'Audio';

23. Buenas prácticas
• Usa nombres de columnas en lugar de SELECT * en código de producción.
• Usa WHERE en cada UPDATE y DELETE, y prueba antes con SELECT.
• Usa transacciones cuando una operación modifica varias tablas.
• Nombra de forma consistente: tablas en plural, FK con el mismo nombre que la PK que referencian, todo en
minúsculas (en Linux los nombres de tabla distinguen mayúsculas).
• Haz respaldos periódicos con mysqldump y prueba restaurarlos.
• Crea índices solo donde se necesiten y verifica con EXPLAIN.
• Valida los datos con restricciones (CHECK, FOREIGN KEY, UNIQUE), no solo en la aplicación.
